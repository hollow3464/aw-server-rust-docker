# AGENTS.md

Guidance for AI agents working in this repository.

## Project overview

This repo contains a GitHub Actions pipeline that tracks upstream
`ActivityWatch/aw-server-rust` (branch `master`), rebuilds a Docker image on
hash changes, and triggers a doco-cd deployment via webhook. There is no
application code here — only workflows, the tracked hash file, and docs.

## Conventions

- `upstream-hash.txt` holds the single latest upstream commit hash. The
  `check-upstream.yml` workflow updates and commits it; the commit push
  triggers `build-deploy.yml`. Do not edit this file by hand unless you
  intentionally want to trigger a build.
- The Docker build context is a clone of the upstream repo at the stored
  hash; its own `scripts/Dockerfile` is used. Do **not** add a root
  `Dockerfile` here (it was removed because the monorepo build is broken).
- Secrets are pulled at runtime from Infisical via OIDC
  (`Infisical/secrets-action`, project `ci-secrets`, env `dev`). Never hardcode
  or commit credentials. Expected env vars: `DOCKERHUB_USERNAME`,
  `DOCKERHUB_TOKEN`, `WEBHOOK_URL`, `WEBHOOK_SECRET`.
- Image tags: `daved3464/activitywatch:<commit-hash>` and `:latest`.

## Common tasks

- Force a rebuild: trigger *Build, push and deploy* via `workflow_dispatch`.
- Change the tracked upstream branch/repo: edit the `git ls-remote` line in
  `.github/workflows/check-upstream.yml`.
- Validate workflow syntax locally after edits (YAML parse), e.g.
  `python3 -c "import yaml,glob; [yaml.safe_load(open(f)) for f in glob.glob('.github/workflows/*.yml')]"`.

## Notes

- `check-upstream.yml` needs `permissions: contents: write` to push the
  updated hash. `build-deploy.yml` needs `id-token: write` for Infisical OIDC.
